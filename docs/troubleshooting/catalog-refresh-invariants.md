# 카탈로그 갱신의 유효 가격·사양 시각·부분 실패를 대조하는 방법

[2026-11-17 실측](../evaluations/catalog-refresh-2026-11-17/README.md)에서는 활성 25개 제품의 과거 가격 검증 상태와 현재 유효 가격 수가 달랐고, JSON 표현 차이가 사양 변경처럼 보였다. 두 현상을 구분하지 않으면 운영 품질을 과대 집계하거나 확인하지 않은 사양의 시각이 바뀌었다고 오판할 수 있다.

## 과거 성공 상태와 현재 유효 가격

`price_status=VERIFIED`만 세지 않는다. 실제 offer의 확인 시각과 72시간 수명을 `CatalogDiscovery.fresh` 및 API 결과로 확인한다. backend가 정지된 동안 예약은 남지만 갱신이 실행되지는 않는다. 이번 실행 전 유효 가격은 CT06 한 개였고, 재조회 후 21개였다. 이것을 48시간 간격의 상시 운영 성공으로 설명하지 않는다.

실패는 실패 관측과 다음 예약을 남기며, 가격 검증 실패의 offer는 추천 근거에서 제외한다. 연속 두 번째 worker 실행에서 관측·월 예약이 늘지 않는지 확인한다. 실패한 같은 상품을 즉시 재호출하거나 가격을 수동 조작해 통과시키지 않는다.

## JSON 표현 차이와 실제 시각 변경

JBL facts는 `1794572702.769`와 `1794572702.769000000`의 표현 차이 때문에 `jsonb::text` 해시가 달라졌다. Sony fact_reviews는 ISO 문자열에서 숫자형 Instant로 바뀌었지만 같은 시각이었다. 전체 해시나 JSON 문자열 차이만으로 clock 변경을 확정하지 않는다.

원래 JSON 숫자 문자열을 보존하고 Instant를 정확하게 비교한다. 이번에는 Node.js 24의 JSON reviver `context.source`와 BigInt 나노초를 사용했으며, JBL 숫자 표현 정규화 후 이전 해시와도 대조했다. 먼저 부동소수점으로 읽고 다시 저장하면 원래 정밀도를 복구할 수 없다. clock이 같다는 검증과 확인 시각을 실제로 재조회해 갱신했다는 주장은 별개다.

## 부분 실패의 세부 원인을 소급 추정하지 않기

Sony는 OPTION_LIST_CHANGED였지만 당시 옵션 개수와 라벨별 일치 정보가 없었다. 빈 목록·새 라벨·중복 중 어느 경우인지 구분할 수 없다. 직접 브라우저 진단도 선택 버튼 대기에서 종료됐으므로 실제 Firecrawl 응답의 변형 원인이나 가격 정확성을 설명하는 근거로 사용하지 않는다.

다음 정상 예약에서 목록 개수·고유 개수·기존 라벨 일치 개수를 기록하도록 로그를 보강했다. 원문과 임의 라벨은 남기지 않고 수용 조건도 유지한다. Marshall의 UNAVAILABLE·PRICE_CONTEXT_MISSING 역시 추가 근거 없이 단종·품절·파서 오류로 단정하지 않는다.

## 원본 DB와 API 검증 분리

최신 서버 기동에는 현재 작업과 다른 migration·정리 스케줄도 포함될 수 있다. 가격 갱신만 확인하는 이번 작업에서는 기존 worker와 CatalogProduct JPA만 실행하고 schema validate를 사용했다. 사양 예약·실제 clock·기존 결정 데이터 보존을 별도로 대조했다.

API는 공개 카탈로그 행만 복사한 일회성 DB에서 검증했다. 원본 사용자 데이터를 복제하거나 원본 DB에 전체 서버를 기동하지 않았다. 운영 서버의 배포·migration 절차를 이 일회성 검증 방식으로 대체한다는 뜻은 아니다. 세부 결과와 미검증 범위는 실측 보고서에 남긴다.
