# 판매처 허용 목록과 실제 갱신 성공을 구분하기

## 증상과 근거

[2026-10-29 실제 Dev 가격 갱신](../evaluations/catalog-2026-10-29/README.md)은 공식 URL 6개 중 4개만 VERIFIED였다. 앞선 직접 HTTP parser probe와 단위 테스트 통과가 실제 provider 성공을 보장하지 않았다. 허용 목록에 든 판매처라도 상품 페이지의 존재·모델·가격 연결을 요청마다 검증해야 한다.

## 확인된 원인

- QCY T13 ANC는 직접 요청도 404였고 Firecrawl 응답의 parser 결과도 PRODUCT_MISSING이었다. URL이 과거에 유효했다는 근거로 판매가를 되살릴 수 없다.
- QCY HT19는 동일 상품 번호의 공개 상품명이 변경되어 이름 기반 color-model identity가 달라졌다. MODEL_MISMATCH가 신규 가격 반영을 막았다. 실제 모델이 바뀌었다고 확정한 결과는 아니며 이름 기반 identity의 오탐 가능성도 드러낸다.
- Apple의 구매 가격은 KRW JSON-LD와 함께 숫자 앞에 ₩를 붙여 제공된다. 기존 일반 가격 라벨 규칙으로는 구매 가격을 대조할 수 없었다. 현재 상품의 구매 선택 링크와 Offer SKU를 함께 연결한 전용 규칙을 추가했고 실제 Firecrawl→DB 저장이 성공했다.
- 삼성 버즈3 FE의 이번 직접 응답은 상품 정보가 없는 공통 페이지였다. 검색 결과나 HTTP 200은 개별 상품 수집 성공의 근거가 아니다. 다른 삼성 상품·실제 Firecrawl까지 불가능하다고 확장 해석하지 않는다.
- 소니 Float Run은 브라우저에서 구매 영역을 확인했지만 기본 Firecrawl 응답에는 그 영역이 없었다. 5초 대기 후에는 영역이 나타났으나 구매 옵션 링크가 있어 기존 단일 상품 검증에서 거절됐다. 별도 브라우저에서는 한 옵션의 선택 후 총액을 확인했지만, Firecrawl action으로 옵션 선택을 시도한 후 스냅샷에도 선택된 항목이 없어 금액 검증에 실패했다. 선택 동작과 스냅샷 중 실패 단계는 확정하지 못했다. 상세 실행과 호출 수는 [평가](../evaluations/catalog-2026-10-29/README.md)에 기록한다. 단위 fixture 성공을 실제 provider 성공으로 취급하지 않고 상품을 비활성으로 유지한다.

## 조치와 재검증

판매 종료 상품은 revision을 올려 비활성화하고, HT19는 같은 공식 상품 번호와 색상 variant 연결을 검토한 후 현재 이름·identity를 등록했다. 자동으로 새 이름을 승인하거나 다른 모델의 사양을 복사하지 않았다. 이 정정은 기존 개인 비교 snapshot을 덮어쓰지 않는다. Apple은 단일 SKU·구매 링크·표시 가격 일치와 불일치·조건부 문구 거절을 회귀 검증한다.

HT19 정정 이후 실제 Firecrawl 재수집은 VERIFIED였다. 소니 실패는 아직 원인을 구분하지 못했으며 상시 운영도 미검증이다. 향후 반복적인 상품명 오탐이 확인되면 안정적인 모델 식별자와 색상 중복 제거를 분리하는 설계를 검토하되, 기존 identity와 저장 데이터의 의미를 변경하기 전에 결정과 migration 영향을 확인한다.
