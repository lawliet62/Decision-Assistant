# 판매처 허용 목록과 실제 갱신 성공을 구분하기

## 상품 식별자 변경 시 가격 재시도 간격

2026-11-03 코드 검토에서 상품 URL이나 식별자를 변경하면 이전 가격을 무효화하는 과정이 `next_attempt_at`도 초기화하는 것을 발견했다. 별도 PostgreSQL 통합 시험에서는 방금 시도한 상품의 식별자를 변경한 뒤 다음 시도 시각이 48시간 뒤에서 1970년으로 바뀌었다. 실제 운영에서 중복 호출이 발생한 것으로 확인된 것은 아니다.

등록 변경 시 기존 판매 가격과 가격 인용은 계속 무효화하되 기존 다음 시도 시각을 보존하도록 수정했다. 통합 시험에서 변경 직후 가격을 사용할 수 없고 worker가 외부 호출이나 월 예약을 만들지 않는 것을 확인한다. 신규 상품은 이전 시도가 없으므로 기존 초기 시각을 사용한다. 실제 판매 URL과 모델의 변경 여부는 별도로 검토해야 한다.

## 첫 기동 시 상품 등록과 가격 예약 순서

2026-11-03 개발 DB에 새 상품을 처음 등록한 직후 가격 worker가 다음 1시간 polling 전까지 시도하지 않은 것을 관찰했다. 당시 로그만으로 첫 예약과 등록의 정확한 실행 순서를 입증하지는 못했다.

별도 PostgreSQL 통합 시험에서 manifest 등록을 의도적으로 지연하고 가격 polling을 1시간으로 설정하자 첫 예약이 등록 전에 실행되어 기한이 된 상품을 바로 처리하지 못했다. 등록 완료 후 예약 스레드에 한 번 더 확인을 넣자 같은 시험에서 한 상품을 즉시 처리했다. 이미 제품별 시도와 월 한도는 DB에서 예약하므로 중복 확인이 호출 제한을 우회하지 않는다. 시험은 외부 수집을 모의했으며 개발 DB의 해당 시점과 정확히 같은 실행 순서를 증명하지는 않는다.

## 삼성·소니 이어폰 상품의 가격 근거 조사 (2026-11-03)

대표 판매처의 이어폰을 추가할 때 SKU가 있는 구조화 가격과 구매 가능한 일반 판매가가 같을 것으로 예상했으나, 두 단계의 응답을 분리해서 확인할 필요가 있었다. 이는 특정 상품을 한 번 조사한 결과이며 판매처 전체의 수집 불가능성을 뜻하지 않는다.

- [삼성 버즈4 화이트 구매 페이지](https://www.samsung.com/sec/buds/galaxy-buds4/buy/?modelCode=SM-R540NZWAKOO)의 직접 HTTP 응답은 버즈4와 버즈4 프로의 여러 SKU를 포함한 `ProductGroup`을 반환했다. 대상 SKU의 구조화 가격은 220,200원이었다. 같은 직접 응답에서 220,200원은 카드 결제 혜택을 포함한다고 안내하는 최대 혜택가 영역에 있었다. 구조화 가격이 일반 구매자의 조건 없는 가격이라는 근거로 취급하지 않는다.
- 같은 삼성 URL의 Firecrawl 기본 `markdown`·`rawHtml` 실제 응답에서 대상 SKU, JSON-LD, 구매 문구와 카드 혜택 문구의 존재를 확인했다. 이 일회성 검사는 각 문구와 가격의 구조적 연결이나 모든 가격 옵션의 조건을 확인하지 않았으므로 검증 성공을 뜻하지 않는다. 직접 HTTP와 Firecrawl 응답은 별개이며 후자의 원문은 보관하지 않았다.
- [소니 WF-1000XM5 블랙 판매 페이지](https://store.sony.co.kr/product-view/110943673)는 직접 HTTP 응답에서 대상 모델명과 JSON-LD가 없었다. 별도 Firecrawl 응답에도 구매 관련 문구는 있었지만 대상 모델명과 JSON-LD가 없었다. 공통 구매 문구는 대상 상품의 구매 가능성이나 가격을 증명하지 않는다. Firecrawl 설정 변경이나 다른 소니 상품에 대한 성공·실패는 확인하지 않았다.

두 Firecrawl 요청은 외부 호출 전 개발 DB의 2026-11 UTC 월 시도 예산에 2회를 예약했다. 일회성 테스트 DB와 임시 검사 코드를 사용했고 원문은 저장하지 않았다. 삼성의 조건 없는 판매가·재고와 소니의 모델·구매 영역을 연결하지 못해 상품은 활성화하지 않았다. 다음에는 실제 Firecrawl 응답에서 정확한 SKU, 일반 판매가의 조건과 구매 가능 상태를 같은 상품 영역에 연결할 수 있는지 확인한다. 가격이나 사양을 추정하여 등록하지 않는다.

## 증상과 근거

[2026-10-29 실제 Dev 가격 갱신](../evaluations/catalog-2026-10-29/README.md)은 공식 URL 6개 중 4개만 VERIFIED였다. 앞선 직접 HTTP parser probe와 단위 테스트 통과가 실제 provider 성공을 보장하지 않았다. 허용 목록에 든 판매처라도 상품 페이지의 존재·모델·가격 연결을 요청마다 검증해야 한다.

## 확인된 원인

- QCY T13 ANC는 직접 요청도 404였고 Firecrawl 응답의 parser 결과도 PRODUCT_MISSING이었다. URL이 과거에 유효했다는 근거로 판매가를 되살릴 수 없다.
- QCY HT19는 동일 상품 번호의 공개 상품명이 변경되어 이름 기반 color-model identity가 달라졌다. MODEL_MISMATCH가 신규 가격 반영을 막았다. 실제 모델이 바뀌었다고 확정한 결과는 아니며 이름 기반 identity의 오탐 가능성도 드러낸다.
- Apple의 구매 가격은 KRW JSON-LD와 함께 숫자 앞에 ₩를 붙여 제공된다. 기존 일반 가격 라벨 규칙으로는 구매 가격을 대조할 수 없었다. 현재 상품의 구매 선택 링크와 Offer SKU를 함께 연결한 전용 규칙을 추가했고 실제 Firecrawl→DB 저장이 성공했다.
- 삼성 버즈3 FE의 이번 직접 응답은 상품 정보가 없는 공통 페이지였다. 검색 결과나 HTTP 200은 개별 상품 수집 성공의 근거가 아니다. 다른 삼성 상품·실제 Firecrawl까지 불가능하다고 확장 해석하지 않는다.
- 소니 Float Run은 브라우저에서 구매 영역을 확인했지만 기본 Firecrawl 응답에는 그 영역이 없었다. 5초 대기 후에는 영역이 나타났으나 구매 옵션 링크가 있어 기존 단일 상품 검증에서 거절됐다. 별도 브라우저에서는 한 옵션의 선택 후 총액을 확인했지만, Firecrawl action의 `click()` 호출 후 스냅샷에는 선택된 항목이 없어 금액 검증에 실패했다. DOM 호출 반환만으로 선택 처리가 성공했다고 판단할 수 없으며, 선택 처리와 스냅샷 반영 중 실패 단계는 확정하지 못했다. 상세 실행과 호출 수는 [평가](../evaluations/catalog-2026-10-29/README.md)에 기록한다. 단위 fixture 성공을 실제 provider 성공으로 취급하지 않고 상품을 비활성으로 유지한다.
- Marshall 상품 페이지는 관련 상품에도 정상 가격 요소를 포함한다. 페이지 전체의 가격 요소가 하나라고 가정한 첫 Firecrawl 검사에서는 PRICE_CONTEXT_MISSING이 발생했다. 구조화 가격과 일치하는 항목을 구분하고 장바구니 영역의 금액을 대조한 재검사에서는 VERIFIED였다. 사양의 서버 원본은 구조화 URL에 내부 렌더링 주소를 사용하지만 브라우저에서는 공식 URL로 표시했다. 공식 canonical·SKU·모델과 함께 확인된 두 주소만 데이터 대조에 허용하며 내부 주소는 요청하지 않는다.

## 조치와 재검증

판매 종료 상품은 revision을 올려 비활성화하고, HT19는 같은 공식 상품 번호와 색상 variant 연결을 검토한 후 현재 이름·identity를 등록했다. 자동으로 새 이름을 승인하거나 다른 모델의 사양을 복사하지 않았다. 이 정정은 기존 개인 비교 snapshot을 덮어쓰지 않는다. Apple은 단일 SKU·구매 링크·표시 가격 일치와 불일치·조건부 문구 거절을 회귀 검증한다.

HT19 정정 이후 실제 Firecrawl 재수집은 VERIFIED였다. 소니 실패는 아직 원인을 구분하지 못했으며 상시 운영도 미검증이다. 향후 반복적인 상품명 오탐이 확인되면 안정적인 모델 식별자와 색상 중복 제거를 분리하는 설계를 검토하되, 기존 identity와 저장 데이터의 의미를 변경하기 전에 결정과 migration 영향을 확인한다.

## 사양 등록과 예약 시도

HT19에 새 사양을 추가한 뒤 최초 개발 기동에서 주간 시도 기록은 생겼으나 새 revision의 확인 시각은 비어 있었다. 기존 revision에는 사양이 없었으며 등록과 예약 작업 중 정확한 선후 관계는 확인하지 못했다. 빈 사양에 시도를 소비하면 다음 기회까지 확인이 지연될 수 있다. HT19, T13 Pro, AirPods Pro 3 worker는 확인 가능한 사양이 등록된 경우에만 시도를 예약한다. 빈 사양에서 호출과 시도 기록이 없는지 통합 테스트로 확인하고, HT19는 실제 페이지를 다시 조회해 개발 DB의 확인 시각과 다음 시도 시각을 확인했다. 상세는 [평가](../evaluations/catalog-2026-10-29/README.md)를 따른다.

## DB 사양 점검 보고서의 시각 형식

자동 사양 확인은 원래 `facts`와 별도의 `fact_reviews`에 기록되지만 기존 보고서는 원래 시각만 읽었다. 실제 개발 PostgreSQL의 JSONB에서는 두 시각 모두 숫자 초 단위로 직렬화되는데, 기존 `Date.parse`는 이 형식을 유효한 시각으로 처리하지 못했다. 따라서 자동 확인 이후에도 점검 필요를 잘못 표시하거나 실제 기한을 누락할 수 있었다. 보고서는 숫자와 ISO 문자열을 모두 읽고 유효한 DB 확인 시각을 반영한다. 실제 시험 DB의 데이터를 사용해 원래 기한은 지났지만 자동 확인 기한은 남은 가상 시점에 점검 대상에서 빠지는 것을 확인했다. GitHub Actions는 DB와 별도로 manifest만 읽는 제한이 남는다.

## 사양 출처의 지연된 응답 본문

기존 사양 조회는 응답 헤더를 받은 뒤 `InputStream`을 읽었기 때문에 본문 전송이 멈춘 경우 요청 제한 시간만으로 전체 읽기가 끝나는 것을 보장하기 어려웠다. 공통 조회는 응답 본문 완료까지 15초와 2MB를 제한하고 시간 초과 시 요청을 취소한다. 로컬 시험 서버가 헤더와 일부 본문을 보낸 뒤 멈추는 상황, 크기 초과와 리다이렉트를 테스트했다. 이 사례는 재현 시험이며 실제 운영 장애가 발생했다는 뜻은 아니다. 실패한 사양은 확인 시각을 연장하지 않고 기존 주간 시도 간격을 유지한다.

## 같은 사양 영역의 복수 모델명

QCY 제조사 사양 검증은 등록 모델명이 포함된 사양 영역을 찾았지만, 그 영역에 다른 `Product Name` 행이 함께 있는 경우도 허용했다. 이런 모호한 페이지가 실제로 관측된 것은 아니다. 사양을 잘못된 모델에 연결하지 않도록 해당 영역의 모델명 행이 정확히 하나이고 등록 모델과 일치할 때만 확인한다. T13 Pro의 ANC·호환성·방수와 HT19의 ANC·방수에서 상충하는 모델명 행을 거절하는 시험을 추가했다.

## Firecrawl이 보안 확인 페이지를 반환한 경우

2026-11-05 개발 앱의 기한이 된 가격 갱신에서 오디오테크니카 2개와 앤커 3개가 `RESOLVED_URL_MISMATCH`로 거절됐다. 추가로 정상 worker에서 조회한 앤커 P41i는 최종 URL이 `https://veritas-hub.cafe24.com/challenge`인 보안 확인 페이지로 이동한 것이 확인됐고, 정상적으로 거절되어 가격을 저장하지 않았다. QCY 판매처 홈페이지의 별도 진단 호출도 같은 보안 확인 페이지로 이동했다. 별도 격리 DB에서 자브라 Evolve2 Buds의 실제 Firecrawl 응답을 가격 worker에 전달한 시험도 같은 코드로 거절됐다. 앞선 다섯 상품과 자브라 상품의 최종 URL은 기록하지 않았으므로 각각 같은 원인인지 확정하지 않는다. 자브라는 48시간이 지난 2026-11-07 07:41 KST 이후에 재진단할 수 있다.

반복 호출을 막기 위해 개발 앱의 가격 갱신을 비활성화했다. 중단 시 진행 중이던 앤커 P31i는 `ATTEMPTED`로 남았고 48시간 다음 시도가 예약되어 있다. 거절된 6개는 실패 상태다. 나머지 제품의 기존 가격도 72시간 유효기간이 지나면 표시되지 않을 수 있다. 사양 갱신은 별도로 활성화했다. 월 예약은 이전 30회에서 자브라 실측, 앱 자동 시도 6회, 홈페이지 진단, P41i 정규 시도를 포함해 39회가 됐다. 실제 원문과 자격 증명은 보관하지 않았다.

후속 단일 상품 시험에서 QCY CT06도 같은 Cafe24 보안 확인 페이지로 이동해 거절됐다. BOSE 1개와 Marshall 2개, Apple 2개는 정상 갱신됐고 젠하이저 1개는 URL 불일치로 거절됐으나 최종 URL을 기록하지 않아 원인이 미확인이다. 자세한 결과와 호출 수는 [평가](../evaluations/catalog-2026-10-29/README.md)를 따른다.

최종 URL 검증을 완화하거나 보안 페이지를 상품으로 취급하지 않는다. 재조회 전에는 각 상품의 48시간 간격을 지키고, 해당 판매처의 접근 조건과 가능한 공식 제공 경로를 확인한다. 각 판매처에서 일부 상품을 한 번 확인한 결과만으로 전체 상품의 상태나 재발 여부를 단정하지 않는다.

대체 경로 조사에서 [Cafe24 Front API 문서](https://developers.cafe24.com/docs/ko/api/front/)는 상품 진열 정보와 Basic 인증을, [인증 정책 공지](https://developers.cafe24.com/cs/front/notice/429)는 개발자 앱의 Front API 사용 설정과 키 발급을 설명한다. 한편 [Admin API 개발 절차](https://developers.cafe24.com/app/front/common)는 쇼핑몰 운영자의 앱 설치와 OAuth 권한 승인을 요구한다. Front API에 Admin API와 같은 판매처별 승인이 필요한지는 확인되지 않았으므로 두 경로를 구분한다. 대상 판매처의 적용 가능 여부, 옵션별 재고와 실제 할인 가격·기간의 제공 여부, 이용 조건 및 비용은 아직 검증하지 않았다. 공식 API 존재만으로 가격 갱신에 사용 가능하다고 판단하지 않는다.

[Front API 상품 상세 문서](https://developers.cafe24.com/docs/en/api/front/?version=2025-12-01)는 상품 번호로 조회할 때 품목·옵션·할인가 리소스를 포함하는 방법과 별도 할인 판매가 조회를 설명한다. [권한 안내](https://developers.cafe24.com/app/front/app/develop/api/scope)는 공개 Front 정보와 판매처 동의가 필요한 Admin 정보를 구별한다. 이 안내와 후속 인증 정책의 적용 관계, 해당 쇼핑몰의 실제 응답, 개별 옵션의 재고 및 비회원 할인 조건·유효기간이 현재 검증 기준을 충족하는지는 확인이 필요하다. 상품 상세 API를 실제로 호출한 결과는 아니다.

## QCY HT10 Hi-Res 사양 출처의 404

2026-11-09 예약 [사양 출처 점검](https://github.com/lawliet62/Decision-Assistant/actions/runs/42611337350)에서 HT10 Hi-Res의 고정 공식 출처 `https://qcystore.co.kr/product/detail.html?product_no=924`가 HTTP 404를 반환해 작업이 실패했다. 나머지 등록 항목은 당시 문구와 제목 점검을 통과했다. 11월 12일 직접 조회에서도 이 출처와 같은 상품 번호의 기존 slug 경로가 404였다. 예약은 실행됐으며 출처 실패를 정상 검출한 사례다. 점검을 통과시키기 위해 실패를 숨기거나 상품을 임의로 비활성화하지 않는다.

검색 색인에는 기존 상품 페이지와 제조사의 AilyBuds Pro+ 안내가 남아 있지만, 검색 색인의 과거 본문을 현재 출처로 취급하지 않는다. 제조사 후보 주소는 조사 도구에서 404 또는 로컬 전송 실패로 조회되지 않아 현재 이용 가능한 대체 근거로 확인하지 못했다. 국내 공식 [펌웨어 안내](https://qcystore.co.kr/article/%EB%8F%84%EB%A7%A4%ED%8A%B9%ED%8C%90/8/16071/)는 직접 조회에서 HTTP 200과 `QCY HT10 Hi-Res 에일리버즈 프로 플러스` 연결을 확인했다. 그러나 본문이 HT10과 HT10 Hi-Res의 업데이트 및 앱 기능을 함께 설명하므로, 특정 모델의 ANC 지원을 단독으로 재검증할 근거로 자동 대체하지 않았다. ANC 지원이 없어졌거나 제품이 단종됐다고 판단한 결과도 아니다.

카탈로그의 기존 근거·확인 시각·상품 등록은 유지했다. 이 읽기 전용 조사는 Firecrawl이나 AI API를 호출하지 않았다. 복구하려면 현재 열리는 공식 출처에서 상품 924 또는 같은 모델의 명시적인 연결과 ANC 지원을 함께 확인하고, 모델 불일치·혼재를 거절하는 회귀 검증까지 수행해야 한다. 하드웨어 근거는 기존 정책대로 보존하되 출처 점검 실패를 미해결 상태로 남긴다.

## 진단 스크립트의 인코딩

삼성 상품의 Firecrawl 응답 진단에서 모델·가격 문자열을 확인한 뒤 문맥 요약이 두 번 실패했다. Windows PowerShell에서 BOM 없는 UTF-8 임시 스크립트의 한글 해석이 깨졌고, 가짜 응답 시험에서도 원래 방식은 구문 오류가 발생했다. 한글 문자열을 비교한 최초의 `구매하기` 미발견 결과는 신뢰할 수 없다. 스크립트를 BOM이 있는 UTF-8로 저장하자 가짜 응답의 한글 문맥 요약과 JSON-LD 확인이 통과했고 실제 재조회에서는 `구매하기`가 확인됐다. 인코딩 문제는 재현됐지만 원래 두 번의 요약 실패와 동일한 예외였는지는 기록 부족으로 확정하지 못한다. 재사용 시 유료 호출 전에 인코딩과 응답 후처리를 가짜 응답으로 확인하고 호출·후처리 실패를 구분한다. 상세 호출 기록은 [평가](../evaluations/catalog-2026-10-29/README.md)를 따른다.

## 젠하이저 구매 영역과 수집 응답

### 2026-11-14: 행사명으로 바뀐 canonical과 제품명

상품 731의 최근 `CANONICAL_URL_MISMATCH`는 직접 HTTP·브라우저 확인에서 `젠사페-` 경로와 `[젠사페]` 제품명 추가로 재현했다. 기존 상품 ID와 다섯 색상 SKU는 유지됐다. canonical만 허용하면 다음 이름 검증에서 다시 실패하므로, canonical·ProductGroup·색상 이름·Offer 경로와 사양 제목을 함께 대조해야 한다. 정확히 확인한 두 형태만 허용하고 임의 접두사를 제거하지 않는다. [평가와 원문 없는 관측](../evaluations/sennheiser-event-2026-11-14/README.md)을 따른다. 수정 파서의 실제 HTML 검증은 통과했지만 예약된 worker의 새 Firecrawl 응답과 DB 반영은 아직 미검증이다. 아래 내용은 이전 진단 당시의 기록이다.

젠하이저 상품 731은 실제 브라우저에서 색상을 고르면 429,000원 합계와 구매 버튼을 표시했다. 반면 Firecrawl 응답을 처리한 전용 시험 파서는 같은 버튼 ID가 두 영역에 있어 처음에 거절했다. 기본 구매 영역으로 좁힌 후에도 주문 동작 속성을 가진 상위 링크가 검출되지 않았다. 브라우저에서는 해당 속성이 있는 링크를 확인했다. Firecrawl에서 속성이 제거된 것인지 요소 구조가 변한 것인지는 구분하지 못했다. 합성 fixture 통과와 문구 존재가 실제 응답의 구매 가능성 검증을 보장하지 않으므로 파서는 적용하지 않았고 상품도 등록하지 않았다. 다음 진단은 수집 응답의 버튼 요소·상위 구조를 확인한 후 기존 가격·재고·모델 경계를 유지할 수 있는지 판단한다. 호출 수와 결과는 [평가](../evaluations/catalog-2026-10-29/README.md)를 따른다.

후속 수집 응답에서는 상위 요소가 링크였지만 브라우저 원본의 `onclick`은 없었고 `#none`은 같은 상품의 절대 URL로 바뀌어 있었다. 이후 파서는 주문 동작 검증을 주장하지 않고, 정확한 상품·색상별 SKU·InStock·동일 금액·구매 영역의 버튼과 허용된 링크 주소를 함께 요구한다. 조건부 금액과 숨김·불일치는 거절하며 실제 응답 한 건을 검증했다. 이 검증은 주문 완료나 모든 색상의 실시간 재고를 보장하지 않으며 사양 갱신과 DB 검증 전이므로 상품은 미등록 상태다.

가격 worker의 실제 응답 DB 시험에서는 첫 호출 후 Gradle `integrationTest`가 `UP-TO-DATE`로 표시돼 새 응답을 사용하지 않았다. 외부 임시 입력의 변경이 Gradle의 테스트 입력에 포함되지 않았기 때문이다. 강제 재실행을 가짜 응답으로 먼저 확인하고 실제 응답으로 다시 시험해 `VERIFIED`와 가격 저장을 확인했다. 외부 응답을 사용하는 일회성 시험은 실행 결과가 재사용되지 않았는지 확인하며, 원문은 시험 후 삭제한다. 이 진단과 이후 상품 등록은 [평가](../evaluations/catalog-2026-10-29/README.md)에 기록한다.
