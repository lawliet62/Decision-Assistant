# AI 품질 문제의 원인을 분리하는 방법

적용 사례: [공식 문서 보완 평가](discovery-quality-2026-10-06.md). 저가 모델이라는 인상만으로 모델 교체를 결정하지 않고, 실패가 발생한 단계와 모델이 실제로 받은 입력을 먼저 확인한다.

## 단계별 확인

| 단계 | 확인할 근거 | 해석할 때의 주의점 |
| --- | --- | --- |
| 검색 | 입력 조건, 고정 검색어, 반환 URL, 공식 범위 필터 | 공식 결과 미확보를 웹 전체의 정보 부재로 해석하지 않는다. |
| 수집·상품 연결 | 요청·resolved·canonical URL, 상태, 정확한 모델·세대 | 다른 모델을 합치거나 지역 별칭을 추측해 거절을 없애지 않는다. |
| 입력 구성 | 파서가 찾은 근거 영역, 발췌 범위·길이 제한 | 원문에 있는 정보가 AI 입력에 포함됐는지 구분한다. |
| AI 추출 | 실제 입력과 제안 값·인용, timeout·응답 오류 | 누락만으로 모델 성능 부족을 확정하지 않는다. |
| 서버 검증 | 인용·값·소유권 검사, 사실 채택·거절 사유 | AI 제안이 있어도 근거 검증에서 거절될 수 있다. |
| 판정·표현 | 최종 facts, 조건별 checks, 설명 생성 주체 | 서버 설명의 유용성을 모델 글쓰기 점수로 취급하지 않는다. |

현재 탐색의 `BLOCK_MISSING`은 지원하는 서버 추출기가 근거 블록을 찾지 못했다는 뜻이다. 전체 HTML에 정보가 없다는 증거가 아니다. `AI_OMITTED` 역시 입력에 정보가 없거나 잘렸는지 확인하기 전에는 모델 책임으로 귀속하지 않는다. 원시 AI 응답을 평가 자료에 남기지 않았다면 복원 가능한 집계와 확인 불가능한 세부 원인을 구분한다.

## 무료 이용과 모델 능력 구분

모델 식별자만으로 실제 계정이 무료 tier인지 판단할 수 없다. 무료 이용 여부, quota·429·timeout, 모델 자체의 추출 능력은 각각 확인할 사항이다. 결제만으로 같은 모델의 추출 정확도가 올라간다고 가정하지 않는다. 요금과 모델 제공 조건이 필요하면 조사 시점의 공식 문서를 확인하고 날짜를 남긴다.

이번 사례에는 429가 없고 12조건이 AI 전에 종료됐다. 이는 무료 quota를 주요 관찰 병목으로 볼 근거가 없다는 뜻이며, 해당 모델의 모든 성능 한계를 부정하는 결론은 아니다.

## 모델 비교가 필요할 때

아래는 **미실행 진단 절차**다. 외부 호출·비용·데이터 전송은 기존 승인 범위 안에서만 수행한다.

1. 정확한 모델의 인용 가능한 사양이 들어 있는 고정 입력과, 정보가 없어 UNKNOWN이어야 하는 입력을 함께 준비한다. 실제 발췌 입력을 사용해 검색 변동을 제외한다.
2. 같은 prompt·입력·출력 schema·검증 규칙으로 현재 모델과 비교 모델을 실행한다. 모델별 설정 차이와 반복 횟수를 기록한다.
3. 올바른 근거 추출, 누락, 잘못된 값·모델 연결, 근거 없는 충족 판정, 검증 후 채택률, 지연·사용량을 따로 평가한다. 하나의 임의 점수로 합치지 않는다.
4. 모델 교체로 추출이 좋아져도 최종 조건 확인·설명이 개선되는지 확인한다. 가격 후보 증가와 서비스 성공률을 구분한다.

고정 입력에서도 오답·누락이 줄고 서비스 결과에 반영되면 모델 변경을 검토할 근거가 된다. 반대로 대부분의 실패가 검색·수집·입력 구성에 있다면 먼저 그 단계의 국소 개선이나 승인된 제품 범위 조정을 검토한다. 비교 표본이 작으면 전체 서비스 효과로 일반화하지 않는다.
