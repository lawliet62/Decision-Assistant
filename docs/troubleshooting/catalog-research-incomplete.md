# 웹 검색 조사 실패와 가격 검증 실패의 구분

2026-11-13 OpenAI 공식 출처 조사에서 Samsung·Sony·JBL 세 건 중 한 건만 조사 제안을 반환했다. [실측과 사용량](../evaluations/catalog-research-2026-11-13/README.md)이 원본이며, 현재 상태는 부분 해결이다. 가격·사양 수집의 정확성은 아직 검증하지 못했다.

## 확인된 사실과 미확인 원인

- Samsung은 실패 상세를 보존하지 못했다. 네트워크·모델·도구·출력 제한 중 무엇이 원인인지 알 수 없다.
- Sony는 API 응답이 `incomplete`였고 입력·출력 token이 반환됐다. 검색 자체의 실패나 판매처 페이지 접근 실패로 단정하지 않는다.
- JBL은 제안을 반환했지만 가격·ANC·기본 호환성은 UNKNOWN이었다. API 성공이 구매 가능한 가격과 검증된 사양 확보를 뜻하지 않는다.

초기 도구 2회·출력 2,000토큰에서 이후 3회·4,000토큰으로 조정했다. 서로 다른 브랜드를 실행했으므로 상한 조정이 성공률을 개선했다는 비교 실험은 아니다. 근거 없이 모델 성능이나 Firecrawl 한도만을 원인으로 보지 않는다.

## 재발 시 진단

1. Secret bootstrap 오류와 API 호출 후 오류를 구분한다. Secret 버전 누락은 네트워크 호출 전에 해결하고 키를 출력하지 않는다.
2. HTTP 상태와 제한된 오류 코드·필드명, `incomplete_details.reason`을 확인한다. 비밀값이나 원문 오류 메시지를 로그에 복사하지 않는다.
3. 실패 응답에도 반환된 token 수를 보존한다. 검색 수와 사용량이 없으면 0원으로 계산하지 않는다. 타임아웃 뒤 서버 처리 여부도 불명확하다.
4. 출처 제안 확보와 모델·SKU·옵션·가격·사양의 독립 검증을 구분한다. 검증 전 결과는 `PROPOSAL_UNREVIEWED`다.

월 실행 슬롯은 외부 요청 전에 DB에 예약하고, 실패·중단·사용량 미확인에도 유지한다. 같은 슬롯으로 재시작해 재청구될 가능성을 줄이며, 다른 과제로 바꿔도 슬롯이 늘어나지 않는다. 재조사가 필요하면 남은 슬롯·크레딧·실패 원인을 확인한 뒤 미사용 슬롯을 명시한다. 자동 재시도는 없다. 요청 제한은 계정 전체의 금액 한도가 아니다.

실패 시 사용량과 안전한 원인을 보존하는 fixture 테스트, PostgreSQL의 슬롯 중복 방지·잘못된 과제/슬롯 거부·카탈로그 미변경 검증을 추가했다. 이 검증은 실제 판매처 접근성과 향후 조사 성공률을 보증하지 않는다. 다음 단계는 후보 근거의 독립 검증이며, 같은 실패를 반복 호출하는 것이 아니다.
