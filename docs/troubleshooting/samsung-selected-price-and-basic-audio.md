# Samsung의 선택 SKU·할인과 기본 연결 근거

## 증상과 근거

삼성닷컴 버즈4 구매 페이지에는 일반·프로 모델, 여러 색상, 즉시 할인, 카드·구독 안내가 함께 있다. JSON-LD 금액이나 최대 혜택가만 읽으면 다른 모델·조건부 금액을 사용할 수 있다. [실측](../evaluations/samsung-buds4-2026-11-13/README.md)에서 선택 화이트 SKU의 실제 220,200원과 API 추천을 검증했다.

## 진단에서 구분한 항목

- 직접 HTTP에는 사양 문단과 ProductGroup이 있지만 가격 상세·수량 UI는 렌더링 후 생성된다. 사양의 직접 조회 성공을 가격 수집 성공으로 해석하지 않는다.
- 알려진 구매 URL과 canonical이 다르다. 동일 모델·색상을 입증한 고정 별칭만 수용하며 다른 modelCode나 query를 같은 상품으로 합치지 않는다.
- 기준가 259,000원, 즉시 할인 38,800원, 혜택가·총액 220,200원을 대조했다. 카드 항목은 금액대 미달성·미선택이었다. 최대 혜택가라는 라벨만으로 전체를 거절하거나 그 숫자를 그대로 신뢰하지 않는다.
- 수량 input property는 1이지만 HTML attribute는 빈 값이었다. 직렬화된 수량 알림과 단가·총액을 교차 검증한다. 기대값 1을 DOM에 주입해 검증을 통과시키지 않는다.
- 오프라인 CLI의 바이트 제한과 가격 파서의 문자 제한은 다른 경계다. 실제 렌더링 크기를 측정해 이 고정 SKU만 300만 자로 제한했다. 다른 상품이나 사용자 URL의 제한은 확대하지 않았다.

## 호환성과 상태

공식 문구가 기본 블루투스 오디오 연결을 OS와 무관하게 허용하고, 앱의 고급 설정 요구사항을 별도로 설명한다. 등록된 정확한 모델·URL·인용에만 Android/iOS 기본 연결 대응을 적용한다. 앱 지원 문구, 다른 출처, 일반 실시간 탐색에는 이 대응을 적용하지 않는다. iOS MEETS는 앱의 고급 설정까지 지원한다는 의미가 아니다.

실제 가격·사양 worker와 두 플랫폼 API 검증은 성공했다. 공개 행사 기간이 확인 시점부터 72시간을 포함하지 않으면 새 할인 가격을 보류한다. 단일 성공은 반복 안정성을 증명하지 않으며 다음 시도 예약을 앞당기지 않는다.
