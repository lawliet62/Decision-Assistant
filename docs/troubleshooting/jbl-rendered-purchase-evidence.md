# JBL 삼성닷컴의 렌더링된 구매 근거 검증

## 증상

JBL 제조사 페이지의 가격·재고 표시와 삼성닷컴의 구매 가능 상태가 달랐다. 브라우저에서는 블랙 SKU를 99,000원에 구매할 수 있었지만 첫 실제 worker는 PRICE_CONTEXT_MISSING을 기록했다. [실측 보고서](../evaluations/jbl-tune-beam2-2026-11-13/README.md)와 [관측](../evaluations/jbl-tune-beam2-2026-11-13/observations.json)을 근거로 한다.

## 원인을 구분한 결과

- JBL 한국 사이트는 제조사 안내와 외부 판매처 연결 역할이다. `commerceSiteFlag:false`, `orderable:false`를 연결된 삼성닷컴의 품절 증명으로 사용하지 않는다.
- 삼성닷컴의 초기 본문에는 정보 확인 전용 안내와 빈 구매 필드가 있다. 렌더링 후 선택 SKU·수량·가격·활성 버튼을 확인해야 한다. 단순 HTTP 200이나 JSON-LD의 InStock만으로 통과시키지 않는다.
- 추가 JSON-LD WebPage의 `@type`은 배열이었다. Jackson 3에서 이를 무조건 문자열로 읽으면 예외가 발생했다. 알려진 단일 Product를 문자열 타입 확인 후 구분하도록 수정했다. 배열형 부가 문서가 있는 fixture를 회귀 검사에 포함했다.
- Firecrawl 응답에는 공개 가격과 수량은 있지만 hidden input은 없었다. `originalPrice` 등 내부 계산 필드를 필수 근거로 삼으면 정상 공개 구매 상태도 거절된다. 원문을 저장하지 않는 진단에서 필드 존재 여부와 안전한 단계 코드만 출력해 차이를 확인했다.

## 수정과 경계

고정 블랙 SKU에서만 충분한 렌더링 대기를 적용한다. 구조화 Product/Offer, canonical, 구매 영역의 모델·SKU, 기준가·총액·최대 혜택가의 동일 금액, 수량 1, 양수 재고 상한, 활성 구매 버튼을 대조한다. hidden input 부재를 허용하는 대신 공개 근거의 교차 대조를 유지한다. 다른 색상·상품·조건부 금액이나 여러 구매 영역으로 확장하지 않는다.

최대 혜택가 표시가 존재한다는 이유로 전체 페이지를 거절하거나 그 금액을 그대로 일반 가격으로 승격하지 않는다. 이 SKU에서는 별도 기준가와 선택 총액까지 같을 때만 수용하고, 차이가 있으면 보류한다. 단위 fixture의 가격은 실제 관측과 구분한다.

교정 worker는 실제 99,000원을 저장했고 ANC/Android API 추천까지 통과했다. 최초 실패의 다음 시도는 유지했다. 48시간 후 반복 안정성은 미검증이다. 다음 실패에서도 타입·렌더링 상태·필드 제거·실제 판매 종료를 분리하며, 유지 비용이 누적되면 에이전트 갱신 비용과 다시 비교한다.

## 판매처와 브랜드를 구분한 migration 검증

전체 업그레이드 통합 검사에서 기존 catalog_known_brand 함수가 jbl-samsung-kr 식별자의 samsung 토큰을 제품 브랜드로 해석하는 문제가 드러났다. V24는 기존 migration을 수정하지 않고 JBL 토큰을 Samsung보다 먼저 인식하며, 해당 JBL 행의 브랜드·상태·version만 보정한다. 가격·사양·revision은 유지한다. CatalogBrandMigrationIntegrationTest는 과거 스키마의 등록 데이터 보존과 새 JBL 브랜드 판정을 함께 검증한다. 스케줄 통합 검사는 새 출처도 mock으로 격리해 실제 외부 HTTP를 호출하지 않는다.
