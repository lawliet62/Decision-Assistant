# 공식 문서 보완 후에도 추천 품질이 개선되지 않은 사례

작성일: 2026-10-06. 상태: **병목 단계는 확인했으나 end-to-end 품질 문제는 미해결**.

후속 조치: 후보 없는 진입을 유지하는 소규모 사전 검토 목록을 도입했다. [ADR 0016](../decisions/0016-curated-catalog.md)과 [초기 검증](../evaluations/catalog-2026-10-06/README.md)에 구현·가격 파서 점검·DB 성능을 기록했다. 제품 범위와 데이터 확보 방식이 달라졌으므로 이 문서의 실시간 검색 문제가 해결됐다는 뜻은 아니다.

## 기록 가치와 기대 결과

공식 문서에서 동일 모델의 사양을 보완하면 가격만 확인한 후보의 조건 판정과 설명이 나아질 것으로 기대했다. 구현 검증과 일부 공개 HTML 파싱은 성공했지만 실제 평가에서는 개선을 입증하지 못했다. 이 차이는 모델 교체나 기능 확장에 투자하기 전에 실패 단계를 분리해야 하는 사례이므로 기록할 가치가 있다.

원본은 [v3 평가 보고서](https://github.com/lawliet62/Decision-Assistant/blob/5c643890aad2aa2b7e6ea5e60bfc8df1de80be27/docs/evaluations/discovery-specs-2026-10-06/README.md)와 그 폴더의 manifest·summary·events·assessment다. 평가 구현과 보고서는 [PR #26](https://github.com/lawliet62/Decision-Assistant/pull/26)에 있으며, 이 문서 작성 시 미병합이므로 근거 링크를 고정 커밋으로 연결했다.

## 관찰한 결과

동일한 고정 15조건을 각 1회 실행했다. 모델은 `gemini-3.5-flash-lite`, 보완 동의는 활성화했고 검색·수집·AI의 실행별 상한은 3·7·1이었다. 직전 v2와 입력은 같지만 실행 날짜와 검색 결과가 달라 통제 실험은 아니다.

| 지표 | 직전 v2 | 이번 v3 |
| --- | ---: | ---: |
| 가격 후보 2개 이상인 조건 | 2/15 | 2/15 |
| 조건 확인 후보 2개 이상인 조건 | 0/15 | 0/15 |
| 반환 가격 후보 합계 | 7 | 8 |
| 설명 평균(agent 평가) | 1.0/3 | 1.0/3 |
| 검색 / 수집 / AI 호출 | 15 / 32 / 3 | 20 / 35 / 3 |

8개 후보 모두 UNKNOWN이고 보완 사양 채택은 0건이었다. 후보 합계는 조건 간 같은 모델의 반복을 포함한다. 잘못된 MEETS를 발견하지 못했지만 충족 판정 표본이 없어 정확도 100%를 의미하지 않는다. 추가 호출이 발생했으나 이 표본에서 품질 이득은 입증되지 않았다. 일반적인 개선 효과가 없다고 확정할 수도 없다.

## 확인한 병목과 원인 판단

15조건 중 12조건은 AI 호출 전에 종료됐다. 7조건은 `NO_OFFICIAL_RESULTS`, 5조건은 `NO_VERIFIED_OFFERS`였다. 최초 검색 결과 75개 중 공식 URL은 33개였고, 수집한 33페이지 중 가격 검증을 통과한 페이지는 11개였다. 모델·색상 중복 제거 후 이어폰 3조건에서만 후보가 남았다.

구매 페이지 검사에는 canonical 불일치 12건과 resolved URL 불일치 6건이 있었다. 보완 검색 5회는 `NO_OFFICIAL_DOCUMENT` 3건, `CANONICAL_URL_MISMATCH` 1건, 수집 502에 따른 `COLLECTION_FAILED` 1건으로 끝났다. 검색 미확보는 공식 문서 자체가 없다는 증거가 아니다. 보완 canonical 실패의 원문과 URL을 저장하지 않아 다른 모델·지역 경로·사이트 변환 중 무엇이 원인인지 확정할 수 없다.

따라서 이번 결과의 주요 관찰 병목은 검색 결과의 공식 범위 연결, 구매 페이지 검증, 보완 문서 도달·수집이다. 모델 성능이 좋아져도 AI에 도달하지 않은 조건이나 서버가 수집하지 못한 문서를 자동으로 복구한다고 볼 수 없다. 그렇다고 AI 추출 품질이 충분하다는 뜻도 아니다. 고정 입력으로 다른 모델을 비교한 실험은 수행하지 않았다.

최종 설명은 검증 결과를 바탕으로 서버가 생성한다. 설명 1점은 서비스 출력의 유용성 평가이며 모델의 자유로운 글쓰기 성능 점수가 아니다. 확인된 사양이 없으므로 가격·예산·미확인 안내에 머물렀다. 사양 보완 원문도 AI에 추가 전송하지 않는 구조다.

## 수행한 조치와 검증의 범위

별도 [공개 HTML 진단](https://github.com/lawliet62/Decision-Assistant/blob/5c643890aad2aa2b7e6ea5e60bfc8df1de80be27/docs/evaluations/discovery-specs-2026-10-06/source-review.md)에서는 정확한 Product Name이 있는 사양 영역으로 검사를 좁혀 T13 ANC의 ANC·호환 플랫폼 2개 사양을 채택했다. 본문 안의 다른 모델 카드가 상품 소유권 검사를 방해하던 국소 문제를 수정한 결과다. 일반적인 모델 동일성 검증을 느슨하게 만들지는 않았다.

이 직접 접근 성공은 실제 검색 경로에서 문서를 확보했다는 증거가 아니다. 구현 테스트·CI 통과 역시 실제 provider 출력의 품질을 보장하지 않는다. 평가와 직접 진단의 성공 건수를 합산하지 않는 것이 핵심이다.

## 다음 진단과 중단 판단

다음 조사에서는 소량의 실패 사례로 검색 URL → resolved URL → canonical → 정확한 모델 사양 영역을 추적하고, 수집 장애와 모델 연결 거절을 분리한다. 필요한 근거만 비밀값 없이 남기며 동일 모델 검증을 약화해 수치를 개선하지 않는다. AI에 도달한 표본의 추출 문제는 [별도 진단 방법](ai-quality-diagnosis.md)을 따른다.

이번 표본만으로 향후 개선 효과가 미미하다고 단정하지 않는다. 다만 여러 브랜드의 웹 구조를 계속 지원해야 하는 비용에 비해 조건 확인율이 오르지 않는다면, 직접 입력·확인한 후보 비교를 핵심으로 두고 자동 탐색을 실험 기능으로 제한하는 범위 조정을 검토할 근거는 된다. 이는 **검토 가능한 대안이며 채택된 제품 결정이나 구현 계획은 아니다**. 제품 범위 변경과 배포 가능 여부는 별도로 결정·검증한다.
