# ADR 0016: 소규모 사전 검토 카탈로그와 정보별 갱신 주기

- 상태: Accepted
- 날짜: 2026-10-06
- 승인: 사용자가 사전 확보 데이터의 가격·비가격 갱신 주기 분리와 측정 후 캐시 판단 제안을 수용하고 구현을 요청했다.

## 배경

실시간 검색 개선에서도 후보·공식 사양을 확보하지 못한 요청이 많았다. [진단](../troubleshooting/discovery-quality-2026-10-06.md)의 결론은 저가 LLM만의 한계로 단정할 수 없다는 것이다. 후보를 사용자가 가져오게 하는 축소안은 클릭 중심 진입의 가치를 잃는다. 따라서 탐색 범위와 운영량을 줄이고, 검토한 데이터를 재사용한다.

## 결정

기본 추천은 무선 이어폰의 운영자 등록 카탈로그(`catalog-v1`, `intake-catalog-v1`)로 전환한다. 초기 5개, 활성 제품 최대 30개다. 기존 모놀리스와 PostgreSQL만 사용하며 별도 서비스·관리 UI·Redis/Caffeine을 추가하지 않는다. 로컬 manifest를 배포 시 반영하고 모델 식별자·공식 출처·인용·확인 시각·revision을 관리한다. 범용 모델 별칭 해석이나 시장 전체 검색은 추가하지 않는다.

| 정보 | 갱신·점검 | 만료·실패 처리 |
| --- | --- | --- |
| 판매가·판매 가능 여부 | 고정 공식 판매 URL을 제품별 24시간 간격 수집 | 가격은 확인 후 24시간 미만만 예산 판정에 사용. 실패는 확인 시각을 연장하지 않는다. 품절·가격 검증 실패·모델 불일치는 새 추천의 판매 정보를 제외 |
| 하드웨어 고정 사양 | 90일마다 수동 출처 점검, 오류 제보·모델 변경 시 즉시 수정 | 기한은 재점검 알림 기준이며 사실의 자동 소멸 기준이 아니다. 기존 근거 유지 |
| 소프트웨어·OS 의존 사양 | 30일마다 수동 점검 | 점검 기한이 지나면 새 추천에서 보류하여 UNKNOWN 유지 |

24시간/30일/90일은 검증을 시작하는 운영 가설이다. 가격의 일간 관측을 2주 수집하고 1일·3일·7일 갱신을 재생해 가격 오차·예산 오판·가용성을 함께 비교한다. 느린 갱신에서도 가격 TTL을 늘리지 않는다. 장기 안정성이나 일중 변동 부재를 이 평가로 입증할 수 없다.

추천 요청은 DB에서 조건을 결정적으로 판정하며 외부 API를 호출하지 않는다. 사용자 조건·메모를 공용 카탈로그나 가격 갱신에 넣지 않는다. 가격 worker만 등록된 공개 URL을 기존 Firecrawl adapter에 전달하며, 월 호출 예약·제품별 다음 시각을 외부 호출 전에 commit한다. 운영자가 갱신을 활성화해야 호출한다. 외부 전송 동의가 없는 카탈로그 비교에서 기존 사용자 URL 수집·AI를 자동 시작하지 않는다.

카탈로그 사양도 사용자 확인 전(`UNREVIEWED`)이며 평가 점수나 확인값을 만들지 않는다. 후보를 만들 때 근거를 복사하고 이후 공용 데이터 변경이 개인 비교·평가 snapshot을 덮어쓰지 않는다. 과거 가격은 확인 시각과 함께 보존하되 조회 시 24시간 규칙을 다시 적용한다.

## 대안과 영향

실시간 검색을 계속 개선하면 제품 범위는 넓지만 요청마다 수집 실패와 비용이 반복된다. 사전 등록은 범위가 좁고 신제품·잘못된 근거 정정이 운영자의 책임이다. 캐시를 더하면 invalidation·만료 관리가 중복되므로 현재 크기에서 DB 기준 성능을 먼저 측정한다. [평가](../evaluations/catalog-2026-10-06/README.md)의 로컬 결과는 도입 유보 근거이며 운영 성능 보증은 아니다.

ADR 0007·0009의 카탈로그 제외 및 매 요청 외부 탐색 경계는 이 기본 경로에 한해 대체한다. ADR 0011·0014의 공식 판매처 검증, 조건의 UNKNOWN/BELOW 구분, 기존 추천 이력 의미는 유지한다. 기존 `intake-v1/v2` 비교와 수동 입력은 호환 경로로 유지한다. 번호 0015는 별도 공식 사양 보강 PR에 예약되어 있다.

구체적인 설정·수정·관측·중단 절차는 [카탈로그 운영](../catalog-operations.md)을 따른다.
