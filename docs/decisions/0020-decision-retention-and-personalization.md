# ADR 0020: 결정 보관·휴지통과 개인화 활용

- 상태: Accepted
- 날짜: 2026-11-14
- 승인: 보관·삭제·복구 및 개인화 활용 분리 제안 수락, CHOSEN·ABANDONED 보관 허용
- 대체 범위: ADR 0018의 즉시 영구 삭제·휴지통 미제공 정책. 소유권·version·연쇄 삭제·백업 공개 제한은 유지한다.

## 결정

CHOSEN·ABANDONED 결정은 보관할 수 있다. 보관은 진행 상태를 변경하지 않고 기본 목록·건수·일괄 선택에서 제외한다. 보관함에서 조회·다시 표시·삭제할 수 있다. 과거의 ARCHIVED 상태는 새 보관 기능과 별개인 기존 값이며 자동 변환하지 않는다.

기록별 개인화 활용 설정을 제공한다. 보관한 결정도 활용을 허용한 경우 사용자가 확인한 성향 기억을 다음 결정에 사용할 수 있다. 기존의 명시적 성향 기억 확인 절차를 유지하며 완료만으로 자동 분석하거나 외부 AI에 전송하지 않는다. 원본별 활용 제어는 기존 성향 기억의 출처를 사용하며 계정 단위 설정이나 별도 학습 모델을 추가하지 않는다.

모든 상태의 삭제는 즉시 휴지통 이동이다. 삭제 시각부터 30일 동안 복구할 수 있으며 정확한 기한은 서버가 판단한다. 삭제 전 진행 상태·보관 여부·개인화 설정·연관 기록을 유지한다. 일반 조회·평가·수집·추천 결과 저장·알림·성향 기억 조회와 활용에서 제외한다. 복구하면 기존 기록을 다시 사용할 수 있고 보관 여부와 개인화 설정도 복원한다. 다른 결정에 이미 복사된 값과 이미 전송한 요청·메일은 되돌리지 않는다.

기한 경과 후에는 복구를 거절하고 매분 최대 100개의 만료 결정을 개별 transaction에서 잠금·재확인 후 영구 삭제한다. 관련 데이터와 모든 상태의 원본 성향 기억은 기존 FK cascade로 제거한다. 백업은 별도 7일 만료 정책을 따른다. 사용자에게 즉시 모든 백업까지 삭제한다고 고지하지 않는다.

## 대안과 영향

기록 보존은 향후 결정 지원에 도움이 되지만 삭제 의사보다 우선하지 않는다. 보관·개인화 활용 중단·삭제를 구분해 안내한다. 성향 기억은 원본 출처가 있는 projection이므로 조회 시 원본의 삭제·활용 설정을 검사한다. 별도 집계나 모델의 재학습을 도입하지 않고 원본 복구 시 이전 기억을 재사용한다.

삭제 관련 백업 복원은 [배포 runbook](../../deploy/README.md)의 순서와 공개 제한을 따른다. 휴지통 이동·복구·개인화 설정 변경 로그도 snapshot 이후 순서대로 재적용해야 한다. 로그는 commit 이후 기록되므로 완전성을 입증하지 못하면 공개하지 않는다. 복원 시각 안내만으로 삭제 이력 재적용을 대체하지 않는다.

복원 기준 시각을 `DECISION_ASSISTANT_RECOVERY_RESTORED_TO`에 ISO-8601 UTC로 설정한다. 잘못된 값은 기동 시 거절한다. 홈 화면에서 한국 시간과 함께 이후 생성·수정·삭제가 반영되지 않을 수 있음을 안내한다. 새 복원 시 설정을 갱신하고 운영자가 안내 종료를 결정하기 전까지 유지한다.

## 검증

`DecisionApiIntegrationTest`가 소유권·version·보관·활용 설정·삭제·복구 기한·purge 전후 FK cascade를 PostgreSQL에서 검증한다. 기존 늦은 AI 결과 및 알림 경합 테스트도 유지한다. `decision-list.spec.ts`는 목록 관리와 휴지통 이동을 검증한다.

`AiDeletionIntegrationTest`는 구조화·평가 생성·평가 재시도에서 외부 응답을 대기시킨 뒤 휴지통으로 이동해 성공·실패 결과가 모두 저장되지 않는지 검증한다. 실행 기록 생성과 결과 변경은 삭제와 같은 부모 잠금 transaction에서 수행하고 외부 호출 중에는 잠금을 유지하지 않는다. 삭제된 경우 404를 반환하며 기존 PENDING 기록은 유지하므로 복구해도 뒤늦은 결과가 나타나지 않는다.
