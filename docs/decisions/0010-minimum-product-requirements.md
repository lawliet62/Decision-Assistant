# ADR 0010: 포트폴리오 MVP의 최소 사양 조건

- Status: Accepted
- Date: 2026-09-24
- Decision: human이 포트폴리오용 MVP에 객관적 최소 조건을 추가하고, 미달 후보 분리·미확인 표시를 추천과 사양 비교에 적용하는 계획을 승인했다.

## 배경

용도·예산·호환성만으로는 사용자가 원하는 사양 하한을 표현하기 어렵다. 현재 우선 목적은 취업 포트폴리오다. 실제 시장 전체를 수집하기보다 입력·근거·판정·불확실성·비용 경계가 연결되는 작은 기능을 완성한다.

## 결정

- `intake-v2`에서 노트북 메모리·저장 공간, 휴대폰 저장 공간·주사율, 태블릿 저장 공간·주사율·전용 펜, 모니터 해상도·주사율, 이어폰 ANC를 선택한다. 모든 조건은 선택 사항이다. CPU 성능·음질·배터리 시간은 첫 범위에서 제외한다.
- 수치·해상도 하한과 명시적인 지원 여부만 서버의 순수 비교기로 판정한다. 저장 공간은 이 기능에서 1TB=1,000GB로 환산한다. 해상도는 가로·세로 픽셀 각각을 비교한다. 전용 펜은 능동형 펜 호환이며 기본 제공을 뜻하지 않는다.
- AI가 반환한 사양은 기존 URL·인용 검사를 거친다. 단일 사양과 명확한 단위·표현만 비교하고 누락·범위·모호함·상충은 UNKNOWN으로 둔다. 인용 검사는 의미 정확성을 보장하지 않으며 자동 사양은 UNREVIEWED를 유지한다.
- 하나라도 BELOW인 후보는 접힌 별도 영역으로 분리하고 UNKNOWN 후보는 기본 목록에 남긴다. MEETS는 수집 사양상 충족이며 검증 완료가 아니다. 각 영역의 기존 순서는 유지한다. 미달 후보도 사람이 비교에 추가할 수 있다.
- 판정 결과는 저장된 조건·사양으로 조회 시 계산한다. 승인한 제품에 사용자 확인 수치가 있으면 표시와 판정 모두 해당 값을 우선한다. 표시용 사양에서 평가값·Constraint를 자동 생성하지 않는다. 기존 점수 평가 확장은 후속 과제다.
- Serper 1회·공개 페이지 최대 5개·AI 최대 1회와 기존 동의·quota를 유지한다. 선택 조건을 검색·AI 입력에 포함하고 메모·identity는 제외한다. 조건 자동 완화·재검색·카탈로그·새 provider를 추가하지 않는다.
- 조건은 기존 JSONB에 저장한다. `intake-v1` 생성·조회·재시도와 기존 단일 용도 데이터는 최소 조건 없이 유지하고, v1에 최소 조건을 넣는 요청은 거부한다. 기존 데이터와 평가 snapshot을 일괄 변경하지 않는다.

## 대안과 영향

충족 근거가 있는 후보만 남기는 대안은 현재 수집 한도에서 후보를 과도하게 줄일 수 있어 채택하지 않았다. 미확인 후보를 남기고 근거를 노출하는 방식으로 비용과 불확실성을 함께 드러낸다.

조건을 늘려도 외부 호출 수는 같지만 검색어와 AI 입력의 토큰은 소폭 증가한다. 엄격한 문자열 해석은 표현이 다양한 실제 페이지를 UNKNOWN으로 남길 수 있다. 이는 후속 품질 개선 대상으로 기록하며 벤치마크 수집이나 범용 사양 추론으로 확대하지 않는다.

검증은 `MinimumRequirementMatcherTest`, `DiscoveryWorkerTest`, `DiscoveryApiIntegrationTest`, `minimum-requirements.spec.ts`를 사용한다. mock 시나리오 재현과 실제 provider의 검색 품질은 구분한다.
