# ADR 0009: 클릭 중심 제품 탐색과 주요 정보 비교

- Status: Accepted
- Date: 2026-09-22
- Decision: human이 후보 없이 시작하는 5개 제품군 추천, 주요 정보 중심 비교, 기존 검색·수집·AI 재사용, 한국·원화 기준 계획을 승인하고 구현을 요청했다.

## 배경

제품명과 상황을 직접 입력하고 평가 항목을 채워야 하는 진입점은 타이핑 부담이 높다. 제품을 아직 모르는 사용자도 용도·예산·호환성을 선택하고 여러 제품의 주요 정보를 직접 비교할 수 있어야 한다.

## 결정

- 기존 5개 제품군에 `intake-v1` 선택 템플릿을 제공한다. 이는 평가 templateVersion과 별개이며 용도 선택으로 평가 weight를 바꾸지 않는다. 명시적으로 선택한 최대 예산은 context와 최대 예산 constraint에 반영한다.
- `discovery`가 있는 생성 요청만 Option 0개로 시작한다. 추천은 같은 Decision의 `ProductDiscovery` 상태 행에서 처리하고 사용자가 승인한 `CandidateSuggestion`만 Option에 연결한다. 기존 제품명·URL 생성 계약은 유지한다.
- 이번 추천에 대해 Serper 조건 검색, 후보 선택 전 Firecrawl 페이지 수집, AI 제품·사양 구조화에 각각 동의를 받는다. 기존 `guided-v1` 동의로 새 전송을 허용하지 않는다. 민감 정보 비포함 확인과 provider 고지를 유지한다.
- Serper에는 템플릿 선택 조건으로 만든 검색어만 보낸다. 최초 추천의 AI에는 조건과 수집한 공개 페이지 발췌만 전달한다. 구매 메모·사용자 identity는 최초 추천 검색·AI에 보내지 않는다.
- 실행마다 Serper 1회, 검색 결과의 공개 페이지 최대 5개 수집, AI 구조화 최대 1회로 제한한다. 제품명 lookup과 같은 월 quota·burst 제한을 사용한다. 실패·부분 성공만 사용자가 version을 확인해 재시도한다. 자동 재검색·자동 재시도는 없다. 추천용 SDK·모델·출력 검증 계층에서도 재호출을 끄고 기존 평가·구조화의 설정은 유지한다.
- 짧은 transaction으로 작업을 claim하고 외부 호출은 transaction 밖에서 실행한다. 실행 중단 후 15분을 넘긴 RUNNING 작업은 실패로 표시하며 오래된 실행 결과는 version 검사로 무시한다. 별도 배포 단위·broker는 추가하지 않는다.
- 제품명과 각 사양은 입력 페이지 URL·원문 인용과 대조한다. 사양 값과 제품명이 인용에 없으면 제외하며 가격에는 통화가 필요하다. 이 검사는 의미 정확성을 보장하지 않으므로 자동 사양은 항상 `UNREVIEWED`다.
- 사양은 평가용 OptionValue와 분리한다. 미확인 항목을 임의로 채우거나 사양을 만족도 rating으로 전환하지 않는다. 승인 시 기존 수집 정보를 재사용하고 재수집·자동 대안 검색을 실행하지 않는다.
- 비교 글 하나가 여러 모델의 출처가 될 수 있다. 새 추천은 Decision 내 제품명으로 중복을 제한하며 세대·구성은 이름과 원문으로 구분한다. 기존 URL lookup의 URL 중복 정책은 그대로 유지한다. 전역 상품 식별·카탈로그를 구축하지 않는다.
- 원문 전체는 보존하지 않는다. 조건·동의·작업 상태·provider/model·prompt/schema version·token/latency metadata와 승인 전 후보의 출처·짧은 인용·조회 시점을 Decision에 귀속해 저장한다. 별도 장기 공유 캐시를 만들지 않는다.

## 영향과 한계

ADR 0006의 한 문장·후보 URL 필수 진입점과 승인한 URL만 수집하는 경계, ADR 0007의 마지막 기능 확장 범위를 이번 승인 범위에서 변경한다. 기존 경로의 동의·소유권·평가 snapshot 의미는 유지한다.

웹 검색과 수집의 품질에 따라 0~5개만 제안할 수 있다. 순서는 추천 순위가 아니며 전체 시장·실시간 최저가·재고·국내 유통을 보장하지 않는다. 원문 인용 검사도 다른 구성이나 문맥을 완벽히 구분하지 못하므로 사용자 확인이 필요하다. 부분 실패는 남은 결과를 보존하고 직접 추가 경로를 제공한다.

검증은 `DiscoveryWorkerTest`, `DiscoveryApiIntegrationTest`, `click-discovery.spec.ts`와 기존 lookup·평가·회고 회귀 테스트로 수행한다. 실제 provider 품질과 계정 비용은 Dev smoke 및 운영 관측으로 별도 확인한다.
