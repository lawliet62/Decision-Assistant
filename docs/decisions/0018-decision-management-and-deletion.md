# ADR 0018: 상태별 결정 관리와 연관 데이터 영구 삭제

- 상태: 일부 대체됨 — 즉시 영구 삭제·휴지통 미제공 정책은 [ADR 0020](0020-decision-retention-and-personalization.md)이 대체한다. 소유권·version·연쇄 삭제·복원 공개 제한은 유지한다.
- 날짜: 2026-11-09
- 승인: human의 목록 UX 계획 승인 및 별도 삭제 정책 선택

## 결정

홈은 상태별 그룹을 기본으로 접고 건수만 보여준다. 복수 상태 선택, 그룹별 10개 페이지, 수정일·생성일·제목·제품군 정렬을 지원한다. 필터·정렬·열린 그룹·페이지는 URL에 보존하며 필터·정렬을 바꾸면 페이지를 초기화한다. 정렬은 현재 소유자의 전체 해당 상태를 서버에서 처리한 뒤 페이지를 반환한다.

소유자가 확인한 삭제는 DB 영구 삭제다. 결정의 후보·조건·평가/AI snapshot·추천 이력·회고·예약 알림 및 해당 결정에서 생성된 모든 상태의 성향 기억을 함께 삭제한다. 공유 카탈로그·계정·다른 결정에 이미 복사된 값은 유지한다. 보관 상태는 삭제가 아니다. `ARCHIVED`로 전이하는 정책을 새로 만들지 않는다.

삭제는 현재 version을 요구하고 결정 행을 잠근다. 수정된 version은 409, 타인/없는 결정은 404다. 중복 요청이 새 데이터를 생성하지 않는다. 수집·알림은 같은 부모 잠금과 순서를 사용한다. 이미 외부로 전송된 요청은 취소하지 못하지만 삭제 뒤 남은 추천 결과를 저장하거나 알림을 새로 발송하지 않는다.

## 대안과 영향

브라우저 숨김은 서버 데이터 통제를 충족하지 않는다. 휴지통은 복구 가능하지만 보존·만료·복원 정책과 worker의 숨김 조건을 확장한다. human은 MVP에서 복구 없는 영구 삭제를 선택했다. 기존 성향 기억의 `ON DELETE SET NULL`을 cascade로 변경하며, 과거 데이터 backfill이나 기존 결정을 삭제하는 migration은 없다.

백업은 7일 보존 뒤 만료 처리한다. 삭제 완료 후 UUID와 시각만 운영 로그에 남기며 로그는 14일 보존한다. 복원 시 삭제 기록을 재적용하고, 기록이 불완전하면 공개를 재개하지 않는다. 외부 provider 자체 보존·이미 전달된 메일은 앱 삭제의 범위 밖이다.

## 검증

`DecisionApiIntegrationTest`는 소유권·복수 필터·동점 정렬·페이지 한계·cascade·성향 기억·동시 수정/중복 삭제·알림 경합을 실제 PostgreSQL로 검증한다. `DiscoveryApiIntegrationTest.lateAiCompletionCannotRecreateADeletedDecision`은 늦은 AI 결과의 재생성을 차단한다. `frontend/e2e/decision-list.spec.ts`는 접힘·필터·정렬·탐색 복원·삭제·모바일을 검증한다.
