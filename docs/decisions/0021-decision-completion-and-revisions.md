# ADR 0021: 결정 완료 결과와 기록 정정·재검토

- 상태: Accepted
- 날짜: 2026-11-16
- 승인: 구매하지 않음도 결정 완료로 분류하고, 완료 후 입력 정정과 다시 검토를 모두 제공한다는 제안 수락.

## 결정과 이유

진행 단계와 결과를 구분한다. 후보 선택과 구매하지 않음은 모두 완료이며 `포기`로 표시하지 않는다. 후보 선택은 실제 구매 완료를 뜻하지 않는다. 기존 `CHOSEN`·`ABANDONED` 값과 과거 고정본은 유지하고 API에 `phase`·`result`를 추가한다. 화면은 두 결과를 한 완료 그룹으로 조회·집계·선택한다. 상태값 전체 변환보다 기존 클라이언트와 데이터 의미의 보존을 우선한다.

완료 기록은 직접 덮어쓰지 않는다. 최신 version으로 기록 수정 또는 다시 검토를 시작하면 현재 draft를 재개하며, 이전 resolution의 고정본을 보존한다. `editMode`와 `revisionBaseId`는 새 완료까지 유지한다. 기록 수정은 이전 완료 기록을 대체한 정정본을 추가하고, 다시 검토는 이전 판단을 유효한 이력으로 남긴다. 정정 중 보류는 허용하지 않는다. 편집 중 화면을 떠나도 진행 내용을 다시 열 수 있다.

새 회고·알림은 resolution에 귀속한다. 과거 회고를 정정본이나 새 선택에 자동 이동하지 않는다. 기존 연결 정보가 없는 회고는 연결 불명으로 표시한다. 정정 중 원본 성향 적용을 중단하고 정정 완료 시 해당 resolution과 연결 불명 과거 회고에서 나온 성향 기억을 활용·재확인 대상에서 제외한다. 해당 기억을 삭제하지는 않으며 다른 결정에 이미 복사된 값은 변경하지 않는다. 연결 불명 기억의 보수적 제외는 잘못된 성향의 재사용을 피하기 위한 선택이다. 다시 검토는 과거의 유효한 성향 기억을 무효화하지 않는다.

두 경로 모두 기존 미완료 회고 알림을 중단한다. 새 후보 선택 완료 시점에 새 알림을 예약한다. 구매하지 않음에는 결정에 대한 수동 회고를 제공하고 제품 기준 성향을 생성하지 않는다. 수정된 입력으로 과거 평가를 다시 계산하거나 표시하지 않는다. 정정·재검토·회고·알림·성향 변경은 동일 부모 잠금 순서를 사용한다.

## 대안과 영향

새 `comparison-v2` 고정본에는 당시 제목도 포함한다. 기존 v1 고정본은 제목이 없는 상태로 계속 읽으며 현재 제목을 과거 제목으로 채우지 않는다.

완료 기록을 직접 수정하면 구현은 작지만 당시 판단과 사후 정정이 구분되지 않는다. 전체 event store 대신 기존 draft와 immutable resolution 관례에 additive 열을 추가한다. 삭제·복구 수명과 외부 전송 경계는 유지한다. 정정 편집을 취소하여 이전 draft 전체를 복원하는 기능은 제공하지 않으며, 편집 상태에서 저장·완료하거나 계속 검토한다.

검증은 `DecisionApiIntegrationTest`의 정정·재검토·소유권·version·회고 연결·개인화 제외 사례와 frontend 브라우저 흐름을 따른다. ADR 0017의 고정본 보존을 유지하고 완료 기록 수정 금지에 명시적 재개 경로를 추가한다.
