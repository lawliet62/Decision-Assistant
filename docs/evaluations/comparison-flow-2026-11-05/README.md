# 조건을 바꾸며 비교하는 MVP 검증

이 문서는 구현 검증과 사용자 평가 준비를 구분한다. 실제 사용자를 대상으로 한 평가는 아직 수행하지 않았다. ChatGPT보다 빠르거나 편리하다는 성과는 주장하지 않는다.

## 문제와 구현

기존 흐름은 후보 없는 추천 진입, 후보 승인, 사양 표, 선택적 점수 평가, 선택·보류·포기, 회고를 이미 제공했다. 다만 추천 조건을 바꾸려면 새 비교를 만들었고, 사양 표에는 선택에 관련된 차이와 공통 정보가 함께 나왔다. Resolution에는 당시 조건과 근거의 고정본이 없었다.

이번에는 이어폰 비교 화면에 같은 후보를 유지하는 조건 편집, 직전 조건 복원, 관련 판정 우선 표시, 공통 충족 조건 접기, 직접 확인·후보 보류·복원을 추가했다. 가격이 있는 후보 사이의 추가 비용과 지원 차이를 보여준다. 더 비싼 후보가 MEETS이고 기준 후보가 BELOW인 조건만 지원 차이로 설명한다. 상대 후보가 UNKNOWN이면 지원 차이로 단정하지 않는다. 배터리 사용 시간은 ANC 상태·측정 조건이 다를 수 있어 수치만으로 순위를 만들지 않는다.

기존 선호 점수의 중요도를 편집할 수 있고 저장 후 기존 평가를 다시 실행한다. 사양 비교·선호 점수·LLM은 합치지 않는다. 점수 없이도 비교하고 결정할 수 있다. 결정 직전에는 저장할 조건과 미확인 사항을 다시 보여주고, 이후에는 당시 snapshot을 표시한다.

## 구현 중 확인한 접근의 한계

- 전체 사양을 먼저 펼치는 기존 화면은 차이와 확인할 항목을 찾기 어려웠다. 전체 표는 유지하되 접고, 현재 조건의 차이와 미확인을 먼저 배치했다.
- 새 카드에 모든 인용·시각을 펼친 초기 화면도 세로 길이가 길었다. 브라우저 screenshot을 확인한 뒤 판정 근거를 펼쳐 볼 수 있게 바꾸고 후보가 2개일 때 빈 세 번째 열이 생기지 않게 했다. 실제 사용자의 읽기 부담 감소 여부는 미검증이다.
- UI 테스트에서 select의 암묵적 label에 선택지 텍스트가 섞이는 문제를 확인해 명시적 접근성 이름을 부여했다. 비동기 보류 응답 전 다음 버튼을 찾던 테스트는 후보 수 변경을 기다리도록 수정했다.
- 정보 누락은 정상적인 결과로 남긴다. 이 변경은 QCY 등을 포함한 카탈로그의 정보 수집 범위나 완전성을 개선한 결과가 아니다.

## 자동 검증

| 대상 | 확인 내용 |
| --- | --- |
| `ComparisonTest` | 상충 ANC·앱만 지원하는 iOS·만료 가격은 UNKNOWN, 사용자 확인은 해당 기능만 덮어써 판정, 수집 자료가 바뀌어도 확인값 유지, 조건 해제·복원 |
| `DecisionApiIntegrationTest.comparisonConditionsConfirmationAndResolutionSnapshotSurviveReopening` | PostgreSQL migration·JSONB 저장, 낡은 version 거절, 확인값 수정, 보류 후 재조회, 과거 snapshot의 판정 불변 |
| `frontend/e2e/comparison-flow.spec.ts` | 실제 Chromium에서 가격 조건 변경/복원, 우선 정보, 직접 확인, 후보 보류/복원/재조회, 선택 기록 재조회, 저장 장애 시 입력 보존, 모든 후보 보류, 모바일 가로 넘침 |
| 기존 guided/minimum-requirements E2E | 후보 검색→입력→평가→선택→회고, 수집 실패 재시도, 저장 충돌·polling 입력 보호, 제품군별 기존 최소 조건 표시 |

브라우저 자료는 `가상 Alpha/Beta`, `example.com` 및 mock backend를 사용한다. 실제 상품 검증과 혼동하지 않는다. 판정·저장 동작은 Java 단위 테스트와 PostgreSQL/API 통합 테스트가 검증한다. 외부 provider나 실제 결제·사용은 이 검증에 포함하지 않는다.

브라우저에서 확인한 [데스크톱 화면](comparison-desktop.png)과 [모바일 화면](comparison-mobile.png)을 보존한다. 두 화면 모두 시험용 가상 제품이다.

검증 명령은 `npm run check`와 `npm --prefix frontend run test:e2e -- comparison-flow.spec.ts guided-decision.spec.ts minimum-requirements.spec.ts`다. 최종 실행 결과는 PR에 기록한다.

## 짧은 사용자 평가 과제

같은 가상 제품 자료를 앱과 범용 AI 도구 양쪽에 제공한다. 실제 판매처 검색 능력이 아니라 주어진 자료로 비교를 진행하는 부담을 관찰한다. AI 도구에는 아래 자료와 과제를 그대로 제공하고 웹 검색은 사용하지 않는다. 모델·제품 버전, 실행 날짜와 참여자 경험을 함께 기록한다. 개인정보나 구매 이력은 수집하지 않는다.

| 가상 자료 | Alpha | Beta | Gamma (추가 과제용) |
| --- | --- | --- | --- |
| 가격 | 50,000원 | 90,000원 | 미확인 |
| ANC | 명시적 미지원 | 명시적 지원 | 미확인 |
| iOS 기본 연결 | 미확인 | 미확인 | 명시적 지원 |
| 배터리 | 최대 6시간, ANC 켬으로 표기되어 ANC 근거와 불일치 | 최대 8시간, ANC 끔 | 미확인 |
| 출처 | 가상 자료 A | 가상 자료 B | 가상 자료 C |

위 자료는 의도적으로 누락과 불일치를 포함한다. 실제 구매 추천 자료가 아니며 배터리 우열을 확정하면 안 된다. 앱에서는 동일 내용을 준비한 시험 비교를 사용하고, 범용 AI에는 같은 표를 붙여넣는다. 제품별 source·시각도 양쪽에 동일하게 제공한다. 실제 조사 시 준비 시간을 별도로 기록한다.

1. 예산 10만원, ANC 필수, iOS 기본 연결이 필요한 사용자의 후보를 비교한다. 충족·미달·미확인을 설명한다.
2. 예산을 7만원으로 바꿨다가 10만원으로 되돌린다. 후보를 다시 입력하거나 표를 다시 만드는 행동을 관찰한다.
3. “Beta를 내 iPhone에 직접 연결해 정상 사용했다”는 추가 자료를 제공한다. 다른 기능까지 지원한다고 바뀌지 않는지 확인한다.
4. Alpha를 비교에서 보류했다가 복원한다. 선택·보류·포기 중 하나를 기록하고 이유와 남은 미확인을 설명한다.
5. 비교를 다시 열어 당시 조건과 확인 근거를 설명한다. Gamma를 추가하는 과제는 양쪽 모두 동일하게 수행한다.

소수 참여자의 탐색적 평가로 시작하며 앱→AI와 AI→앱 순서를 번갈아 배정한다. AI 입력은 자유롭게 허용하고 앱 조작만 유리한 지시를 주지 않는다. 중도 포기와 진행자의 도움도 기록한다. 유료 API 실험이나 자동 대량 호출은 이 준비에 포함하지 않는다.

| 관찰 항목 | 기록 방식 |
| --- | --- |
| 비교 완료 시간 | 자료 제공부터 결정과 이유 기록까지, 준비·대기 시간 별도 |
| 조건 재설명·후보 재입력 | 사용자가 반복한 내용과 횟수. 클릭 수와 혼합하지 않음 |
| 중요한 미확인 누락 | iOS 확인 전 지원으로 가정했는지, Gamma 가격 누락을 놓쳤는지 |
| trade-off 설명 | 추가 4만원과 ANC 차이를 구분하고, 배터리 우열을 단정하지 않는지 |
| 기록 재이해 | 당시 예산·확인 근거·남은 미확인을 다시 설명할 수 있는지 |
| 관찰 메모 | 도움 요청, 되돌리기 실패, 문구 오해, 예상 밖 사용 방식 |

결과 입력 양식: `참여자 익명 ID / 도구·버전·순서 / 완료·포기 / 소요 시간 / 반복 입력 / 놓친 미확인 / 선택 이유 원문 / 도움 / 관찰`. 정답 추천 제품을 맞히는 시험으로 평가하지 않는다. 사용자 효과에 대한 결론은 이 관측 이후에 작성한다.

## 남은 한계

- 후보 없는 추천과 카탈로그 누락 정책은 유지한다. 제조사 공개 여부 조사, OCR, 추가 수집 AI, 자동 재확인 범위 확대는 하지 않았다.
- 직접 확인 UI는 ANC와 기본 연결 호환성, 기존 수치 입력에서 다루는 값에 한정한다. 배터리 조건 정규화와 기기별 세부 기능 행렬은 없다.
- 가격 차이는 확인 가능한 가격이 있는 후보만 대상으로 한다. 판매처의 현재 가격·재고 보증이 아니다.
- 비교에서의 보류는 화면의 비교 대상만 줄인다. 기존 점수 평가의 후보를 삭제하거나 자동 제외하지 않는다. 선택 단계에서도 후보 자체는 남는다.
- 한 단계 조건 복원은 화면을 떠나면 사라진다. 영속 변경 이력은 결정 시점의 snapshot으로 제공하며, 예전 기록은 소급 복원하지 않는다.
- 비교 조건과 기존 평가용 Constraint는 별개다. UI가 설명하지만 개념을 혼동하는지는 사용자 평가에서 확인해야 한다.
- 사용자 효과는 미검증이다. 이번 결과는 작동하는 비교 흐름과 평가 준비이며, 범용 AI보다 우수한 제품이라는 증거는 아니다.
