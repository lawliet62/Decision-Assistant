# 개발 DB의 CT06 기한 도래 갱신

## 실행 조건

2026-11-14 19:41 KST에 확인했다. main은 병합된 PR #64·#66을 포함한 `d58c4a9`이며 기존 개발 DB 컨테이너는 정지돼 있었다. 기존 볼륨을 유지해 시작했다. 개발 DB의 기한 도래 제품은 CT06 하나, 월 예약 시도는 77회였다. 다음 시도 시각 2026-11-14 15:42 KST를 앞당기지 않았다.

기존 애플리케이션을 local/offline 프로필로 실행했다. CT06 직접 HTTP·카탈로그 가격 refresh만 활성화하고 Firecrawl·AI·검색·메일·사양 refresh는 껐다. 시작 직후 기존 startup worker가 기한 도래 행을 처리하게 했다. 수동 가격 입력이나 시도 시각 변경은 하지 않았다. 월 상한 700·48시간 예약과 엄격한 모델·옵션·가격·재고 검증을 유지했다.

## 결과와 시각

CT06은 `RESOLVED_URL_MISMATCH`에서 `VERIFIED`, 46,900 KRW로 갱신됐다. [실행 전](before.json)과 [실행 후](after.json)는 공개 상품 메타데이터만 보존한 PostgreSQL JSON이다. 시각 정밀도를 유지하기 위해 숫자형 Instant를 JavaScript 부동소수점으로 다시 직렬화하지 않았다. 개인정보·전체 HTML·비밀은 포함하지 않는다.

- 시도: 2026-11-14T10:45:21.232529Z
- 가격 확인: 2026-11-14T10:45:22.676114900Z
- 다음 시도: 2026-11-16T10:45:21.232529Z, 즉 11월 16일 19:45 KST 이후
- 월 예약 시도: 77 → 78. Firecrawl·OpenAI 호출은 0회다. 직접 조회도 같은 월 예약을 소비한다.
- 다른 활성 24개 제품의 가격·다음 가격 시도 시각 변경은 SQL 대조에서 0건이었다. 다른 제품별 사양 예약도 변경하지 않았다.

main manifest 반영으로 Apple 두 제품의 revision은 1에서 2로 올라갔다. iOS SOFTWARE 근거가 등록됐고 구매 URL·identity가 같아 기존 가격·가격 예약은 보존됐다. revision 정책에 따른 이전 fact_reviews 초기화와 원래 하드웨어 근거 시각 보존을 구분한다. 이번 실행에서 사양 확인 시각을 재조회 없이 연장하지 않았다.

## 실제 API 검증

[기본 API 관측](api-results.json)은 외부 동의 false인 실제 개발 backend 결과다. 5만원·필수 조건 없음의 첫 묶음에는 더 저렴한 제품 다섯 개가 먼저 나왔다. [CT06 추가 탐색](ct06-api.json)에서는 기존 refresh API로 두 번째 묶음을 요청해 CT06 `RECOMMENDED`·46,900원과 DB와 같은 가격 시각을 확인했다. 검증을 위해 순위·한도·데이터를 조작하지 않았다. 이 추가 탐색에서는 가격 refresh도 비활성화했고 월 시도 수는 그대로였다.

25만원·iOS·ANC 필수에서는 QCY T13 Pro·Samsung 버즈4·AirPods 5 세 후보가 RECOMMENDED였다. 기존 가격 확인 시각을 유지했으며 미확인 후보는 UNKNOWN으로 남았다. 이번에 생성한 임시 결정 세 건은 API DELETE 204로 정리했다. 검증용 backend는 종료했고 기존 개발 DB는 실행 상태로 남겼다. 상시 backend 자동 운영이나 운영 배포를 수행한 것은 아니다.

## 남는 작업

활성 제품은 25개·10개 브랜드, 72시간 이내 유효 가격은 23개다. HT10의 PRODUCT_MISSING과 젠하이저의 기존 CANONICAL_URL_MISMATCH는 남아 있다. 현재 도래한 가격 시도는 0개다. Sony·JBL·Samsung의 다음 가격 시도는 각각 11월 15일 20:11·21:34·22:13 KST 이후다. 해당 모델의 실제 반복 갱신, 젠하이저 수정 파서의 새 수집 응답·DB 반영, Sony의 GitHub 403과 HT10 404 대응은 여전히 미완료다. 전체 Goal을 완료로 처리하지 않는다.
