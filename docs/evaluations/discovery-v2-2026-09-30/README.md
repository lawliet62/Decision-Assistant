# 상품 근거·호환성·설명 v2 평가

2026-09-30 KST. 고정 15조건을 한 번씩 실행했고 모두 해당 worker의 완료 계측을 확보했다. **검증·설명의 특정 결함은 수정됐지만, 조건을 확인한 추천 후보 확보는 여전히 부족하다.** 반환 후보는 3개이며 모두 확인 필요다. 기본 추천 2개 이상은 0/15로 개선되지 않았다.

## 실행과 비교 범위

- 앱 실행 코드: commit `600957a`, 정책 `official-kr-v2`, prompt `discovery-v6`, schema `discovery-v2`. 문서 추가 이후에도 실행 코드는 이 revision과 같다.
- 같은 [15조건](../../../scripts/discovery-evaluation/cases.json), A안 질의, Serper·Firecrawl·Gemini `gemini-3.5-flash-lite`를 사용했다. 회당 검색 1·수집 최대 5·AI 최대 1을 유지했다.
- 실행 08:28:02~08:43:31, 약 928초. 조건 생성 간격은 65초다. 중간 변경·실패 자동 재시도·선택적 재실행이 없다.
- 다른 backend가 없는 상태에서 독립 평가 JAR를 실행했다. [manifest](manifest.json)에 commit·빈 작업 diff·입력·JAR hash를 기록했다. 실제 페이지 직접 검토와 파서 재생은 서비스 15회와 분리했다.
- 종료 후 평가 JVM과 DB 연결이 사라진 것을 확인했고 개발 서버의 기존 종료 상태를 유지했다.
- 비교 대상은 [이전 A안 v1 15회](../discovery-a-2026-09-30/README.md)다. 기준 검색 방식 15회는 다시 실행하지 않았다. v1에는 수집 429가 있었고 검색 결과도 달라졌으므로 차이를 코드의 효과로만 해석하지 않는다.

## 2. 충족 오판·가격·근거 없는 설명

- 반환 후보의 최소 조건 2개와 호환성 3개, 총 5개가 모두 UNKNOWN/MISSING이다. 잘못된 MEETS는 0건이지만 MEETS 자체가 0건이므로 충족 판정의 정확도가 높다고 결론 내릴 수 없다.
- 가격 3건은 상품 구매 영역의 판매가와 구조화 Offer가 일치했다. 검토한 설명 3건에서 근거 없는 용도 성능 보장은 발견하지 못했다. 미확인을 충족으로 바꾸는 기존 모순도 재현되지 않았다.
- 이전에 최소 사양 선택이 없어 기본 추천되던 T17APP은 iOS 근거가 없으므로 UNKNOWN으로 분리됐다. 기존에 저장한 v1 후보의 의미·설명은 바꾸지 않는다.
- LG 회원 가격과 RAM·SSD 미달은 별도의 **실제 공식 HTML → 고정 빌드 파서 진단**에서 수정 효과를 확인했다. 회원 가격은 CONDITIONAL_PRICE, 분리한 사양 검사에서는 8 GB·256 GB가 두 요구 조건에 BELOW였다. 이 15회 검색에서는 그 결과를 후보로 반환하지 않았으므로 별도 진단을 실제 탐색 성공으로 더하지 않는다.

회귀 테스트는 최대·옵션·상충 사양, 다른 모델·구성, 항목과 값의 오연결, 앱 OS와 기본 호환성 혼동, 이전 버전 보존도 검증한다. 전체 시장의 의미 정확성을 보증하는 검사는 아니다.

## 5. 설명 유용성과 남은 과제

세 후보 모두 **1/3점**, 평균 1.0점이다. v1 다섯 설명의 평균은 0.4점이었지만 표본 구성이 달라 직접 성능 향상률로 해석하지 않는다. 같은 T13 ANC의 두 조건에서는 근거 없는 적합성 단정(0점)이 가격·미확인 고지(1점)로 바뀌었다. T17APP은 양쪽 모두 1점이며 v2에서 iOS 미확인 이유가 명확해졌다. 조건과 확인 사양을 연결하는 2·3점 설명은 이번에도 없다.

수정한 가격 조건·사양 정규화·호환성 분리·설명 일치는 회귀 테스트와 직접 파서 진단으로 확인했다. 다만 실제 추천 서비스의 핵심인 후보 확보는 해결되지 않았다. 다음 검토 대상은 공식 개별 상품 확보와 수집 URL 연결, 실제 확보한 페이지의 텍스트·이미지 사양 범위다. 이번 결과만으로 B/C·추가 AI 호출·리뷰 수집의 비용 대비 이득이 입증된 것은 아니며 도입하지 않았다.
